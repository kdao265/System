# Design system direction

## Status

This is a documentation foundation, not a UI redesign or an implemented design system. No existing interface or tokens are present in the repository. Colors, typography, spacing, iconography, and components remain to be proposed.

## Principles

- Build an original identity inspired by game/anime System interfaces.
- Make tasks, deadlines, progress and recovery information easy to read and act on.
- Distinguish EXP from money and estimated progress from verified evidence with explicit labels, not color alone.
- Present health as workload/energy/recovery estimates; avoid medical language.
- Show failure and waivers without implying that punishment is mandatory.
- Account for keyboard access, visible focus, readable contrast, and reduced motion in future designs.

## Future design records

Record agreed tokens and reusable components here with purpose, states, accessibility behavior, and links to examples. Include loading, empty, error, disabled and success states when relevant. Tie proposals to requirements and [UI flows](ui-flows.md); do not invent behavior in mockups or encode configurable criteria in presentation logic.
